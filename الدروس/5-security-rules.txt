=========================================
الدرس الخامس: قواعد الأمان والحماية في قاعدة البيانات
=========================================

مرحباً بك! في هذا الدرس سنتناول جانباً في غاية الأهمية في تطوير التطبيقات الحقيقية وهو "قواعد الأمان والخصوصية" (Security Rules).
بما أننا نستخدم واجهات أمامية مباشرة (Client-Side Javascript) للاتصال بالفايربيس، فمن الضروري حماية قاعدة البيانات حتى لا يتمكن أي متسلل من تعديل الأرصدة أو قراءة كلمات مرور الأعضاء الآخرين من خارج واجهة التطبيق الرسمية.

1. أين تُكتب قواعد الأمان؟
------------------------
تُكتب قواعد الأمان داخل لوحة تحكم Firebase Console في التبويب الخاص بـ Realtime Database تحت عنوان "Rules" بصيغة كائن JSON.

2. نموذج القواعد المقترح للاستوديو (Database Security Rules)
-----------------------------------------------------------
إليك كود القواعد الاحترافي الذي يضمن أمان المنظومة بالكامل:

{
  "rules": {
    // 1. صلاحيات عامة: يجب أن يكون المستخدم مسجلاً للدخول لقراءة أي شيء
    ".read": "auth != null",
    
    // 2. حماية بيانات المستخدمين
    "users": {
      "$uid": {
        // يسمح للعضو بقراءة حسابه الخاص فقط، ويسمح للأدمن بقراءة كل الحسابات
        ".read": "auth != null && (auth.uid == $uid || root.child('users').child(auth.uid).child('role').val() == 'admin')",
        
        // الأدمن فقط هو من يستطيع تعديل بيانات الحسابات أو إنشاءها
        ".write": "auth != null && root.child('users').child(auth.uid).child('role').val() == 'admin'",
        
        // منع أي عضو من تعديل رصيده المالي بنفسه نهائياً
        "balance": {
          ".write": "auth != null && root.child('users').child(auth.uid).child('role').val() == 'admin'"
        }
      }
    },
    
    // 3. حماية الصناديق المالية العامة (الصندوق التشغيلي ومحفظة التكافل)
    "funds": {
      // يسمح للجميع بالقراءة لرؤية الأرصدة في الشاشة
      ".read": "auth != null",
      // الكتابة والتعديل محصورة فقط بالأدمن
      ".write": "auth != null && root.child('users').child(auth.uid).child('role').val() == 'admin'"
    },
    
    // 4. السجل المالي العام (Transactions)
    "transactions": {
      ".read": "auth != null",
      // لا أحد يستطيع تعديل أو حذف السجل المالي، يسمح فقط بإضافة معاملات جديدة (push) بواسطة الأدمن
      ".write": "auth != null && root.child('users').child(auth.uid).child('role').val() == 'admin' && !data.exists()"
    },
    
    // 5. المخططات والمهام (Tasks)
    "tasks": {
      ".read": "auth != null",
      // يسمح للأعضاء المعنيين بالمهمة فقط بتعديل المهام الفرعية (subtasks)
      "$task_id": {
        ".write": "auth != null && (root.child('users').child(auth.uid).child('role').val() == 'admin' || data.child('executors').val().contains(auth.uid))"
      }
    },
    
    // 6. غرف النقاش (Discussions)
    "discussions": {
      ".read": "auth != null",
      // يسمح بإرسال الرسائل (الكتابة) وحذفها لكاتب الرسالة أو للأدمن
      "$task_id": {
        "$msg_id": {
          ".write": "auth != null && (!data.exists() || data.child('senderId').val() == auth.uid || root.child('users').child(auth.uid).child('role').val() == 'admin')"
        }
      }
    }
  }
}

3. شرح كيف تعمل القواعد البرمجية (Validation & Authorization):
---------------------------------------------------------------
* `auth != null`: تتأكد أن الشخص الذي يحاول الاتصال قد مر عبر بوابة تسجيل الدخول.
* `root.child('users').child(auth.uid).child('role').val() == 'admin'`: هذا السطر البرمجي يبحث في جذر قاعدة البيانات عن المستخدم الحالي ويتحقق هل يملك رتبة `admin`. إذا كان نعم، يمنحه صلاحية الكتابة والتعديل.
* `!data.exists()`: تُستخدم للتأكد أن العملية هي "إضافة جديدة فقط" (Insert) وليست تعديلاً أو حذفاً لبيانات تاريخية مخزنة مسبقاً، وهذا هام جداً لحماية سجل المعاملات المالية من التزوير.

تلميح للمبتدئين:
في بيئة التطوير المحلية (Development)، قد نترك القواعد مفتوحة مؤقتاً لتسهيل العمل، ولكن قبل نشر التطبيق للجمهور أو تفعيله في الاستوديو الفعلي، يجب تطبيق هذه القواعد فوراً لضمان عدم تمكن أي شخص من قرصنة الأرصدة أو التلاعب بنسب المساهمات.
