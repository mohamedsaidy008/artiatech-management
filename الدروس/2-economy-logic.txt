=========================================
الدرس الثاني: المنطق المالي والترحيل الحسابي (Economy Engine)
=========================================

أهلاً بك! هذا الملف يشرح الكود الحسابي المعقد في صفحة الاقتصاد (`js/economy.js`). المنظومة المالية هنا تفاعلية وتضمن عدم حدوث أي تلاعب مالي أو خطأ محاسبي.

1. قواعد تقسيم إيراد المشروع (The 50/30/20 Rule)
----------------------------------------------
عند إغلاق مشروع بقيمة (Revenue)، نقوم بتوزيع الأرباح كالتالي:
- فريق العمل المنفذ: يأخذ 50% بالتساوي.
- الصندوق التشغيلي للاستوديو: يأخذ 30%.
- محفظة التكافل والمساهمة: تأخذ 20%.

في الكود، قمنا ببرمجة ذلك كالتالي:
   const share50 = revenue * 0.50;
   const share30 = revenue * 0.30;
   const share20 = revenue * 0.20;

2. قاعدة استبعاد المنفذين (Exclusion Logic)
-------------------------------------------
العضو الذي نفذ المشروع واستلم نصيبه المباشر من الـ 50%، لا يجوز له قانوناً ورياضياً أن يشارك بقية الأعضاء في الـ 20% التكافلية الناتجة عن مشروعه.
كيف برمجنا ذلك؟
نقوم بفلترة الأعضاء عند التوزيع:
   const executors = taskData.executors; // منفذو المشروع
   const eligibleMembers = Object.keys(users).filter(uid => !executors.includes(uid)); // المؤهلون

بعد ذلك نقوم بإعادة توزيع نسب هؤلاء الأعضاء المؤهلين لتصبح نسبتهم الإجمالية مساوية لـ 100% (تسمى هذه العملية رياضياً بالـ Normalization):
   const sumEligibleShares = eligibleMembers.reduce((sum, uid) => sum + (baseShares[uid] || 0), 0);
   
   if (sumEligibleShares > 0) {
       const relativeShare = baseShares[uid] / sumEligibleShares;
       const payout = share20 * relativeShare; // الحصة الفعلية للعضو المستحق
   }

3. نظام الترحيل للشهور الجافة (Unpaid Months Rollover)
------------------------------------------------------
إذا حددنا نسب مساهمة في شهر (يناير) مثلاً، ولكن الاستوديو لم يدخله أي مال (المحفظة صفر)، يجب ترحيل حقه للشهر التالي (فبراير).
كيف قمنا ببرمجة المتوسط الحسابي للترحيل؟
أولاً، نحتفظ بقائمة الأشهر غير المدفوعة في الفايربيس تحت العقدة `unpaid_months`.
وعند التوزيع المالي، نقوم بجمع نسب العضو لجميع الشهور التراكمية وتقسيمها على عدد الشهور للحصول على المتوسط:
   let totalShare = 0;
   let monthsCount = 0;
   
   unpaidMonths.forEach(m => {
       if (monthlyAllocations[m] && monthlyAllocations[m][uid]) {
           totalShare += monthlyAllocations[m][uid].share;
           monthsCount++;
       }
   });
   
   baseShares[uid] = monthsCount > 0 ? (totalShare / monthsCount) : 0;

4. نظام السجل المالي (Financial Ledger) ونظام السحوبات
-------------------------------------------------------
لمنع التعديل الصامت للبيانات:
- كل عملية مالية يتم حفظها في عقدة مستقلة `transactions` فيها تفاصيل (actor, amount, type, desc, timestamp).
- عند سحب رصيد، يتم إنشاء طلب في الفايربيس بحالة `pending` (معلق).
- يملك الأدمن فقط صلاحية تحويل الحالة إلى `approved` (مقبول)، ليتم الخصم الفعلي للرصيد وتوثيق العملية في السجل المالي تلقائياً.

تلميح للمبتدئين:
المعادلات الرياضية الصارمة تمنع الغبن والمحسوبية داخل بيئة العمل الجماعي، وتحويلها لكود برمجي يضمن تطبيقها بدقة 100% دون أي خطأ محاسبي بشري.
